# آزمایش خصوصی میکروفن وایت‌هت

این مرحله صوت میکروفن را حین ضبط از صفحهٔ `/voice-pilot` به BFF و Kotlin می‌رساند و در پایان هر نوبت متن قابل بازبینی برمی‌گرداند. صفحه نسخهٔ آزمایشی ورودی صوت است. پاسخ شنیداری دوطرفه و اجرای تحلیل از متن نیازمند مرحلهٔ اتصال بعدی‌اند.

## محیط بدون هزینه

گردش‌کار موجود S2 Reference روی PR، محیط موقتی HTTPS/Keycloak/PostgreSQL با دو BFF و یک Kotlin API می‌سازد. Chromium از میکروفن ساختگی و Kotlin از transcriber ساختگی استفاده می‌کند. تست شامل دریافت متن بعد از ارسال قطعه‌های صوت، رد درخواست بدون CSRF، رد فضای نامعتبر، سقف بایت متناظر ۱۵ ثانیه، لغو، رد تلاش چهارم و کنترل RLS است. پس از اجرا محیط حذف می‌شود و فقط گزارش پالایش‌شده در Actions می‌ماند.

## روشن‌کردن پایلوت واقعی روی محیط شخصی یا staging خصوصی

1. یک محیط مستقل HTTPS از چیدمان فعلی سفید‌هت با PostgreSQL آزمایشی، حساب runtime بدون SUPERUSER/BYPASSRLS، IdP آزمایشی و BFF موجود بساز. یک و فقط یک نمونه Kotlin برای مسیرهای پیلوت قرار بده؛ اتصال باز WebSocket در همان نمونه می‌ماند. BFF می‌تواند با همان session store پشت پراکسی بماند. از دادهٔ ساختگی استفاده کن و مرحلهٔ مهاجرت موجود را با حساب مالک DB روی محیط آزمایشی اجرا کن. به حساب runtime مجوز SELECT/INSERT/UPDATE روی `voice_pilot_attempts` بده؛ شرط RLS فعال می‌ماند.
2. با UI موجود فضای اختصاصی بساز و شناسه UUID را از `/api/v1/me` ثبت کن. صفحه خودش فقط فضای OWNER را پیدا می‌کند. در Kotlin، `WH_VOICE_PILOT=1`، `WH_VOICE_PILOT_WORKSPACE` و `WH_VOICE_PILOT_API_KEY` را تنظیم کن. در BFF فقط `WH_VOICE_PILOT=1` لازم است. کلید API فقط در secret manager یا محیط فرایند Kotlin قرار گیرد.
3. وارد حساب مالک آزمایشی شو، `/voice-pilot` را باز کن و یک جملهٔ ساختگی فارسی با عدد و ارز بگو. متن را بررسی کن و نتیجه، زبان، زمان شروع و تأخیر متن نهایی را بدون رونوشت یا کلید ثبت کن. لغو را هم کنترل کن.
4. برای خاموش‌کردن ورودی صوت هر دو flag را بردار و سرویس‌ها را restart کن. پایگاه شمارنده را برای جلوگیری از مصرف مجدد نگه دار. فضای اختصاصی به هر قصد صوت حداکثر سه تلاش در کل دارد. هر تلاش پیش از تماس خارجی ثبت می‌شود و با لغو یا پاسخ مبهم دوباره مصرف‌پذیر نمی‌شود.

## هزینه و داوری

- صوت ورودی PCM ۲۴ کیلوهرتز تک‌کانالِ ۱۶ بیتی است. Kotlin حداکثر ۷۲۰٬۰۰۰ بایت برای هر تلاش و ۴۰ ثانیه عمر اتصال را اعمال می‌کند. سقف ۴۵ ثانیه صوت ارسالی برای سه تلاش در یک workspace است. برآورد صوت با نرخ رسمی ۰٫۰۱۷ دلار در دقیقه حدود ۰٫۰۱۲۷۵ دلار برای ۴۵ ثانیه است و مبلغ نهایی از رسید بررسی می‌شود. [مستند نرخ](https://developers.openai.com/api/docs/models/gpt-live-transcribe)
- داوری C3 روی پروندهٔ G001 بخش مستقلی است. دو فضای آزمایشی جدا، سهیم در یک policy و کد ثابت، و دو پیکربندی مجزا برای مدل پایه و کاندید لازم‌اند. برای G001 سقف پیشنهادی مجموع ۰٫۲۵ دلار، حداکثر دو اجرای مولد و یک اجرا برای هر مدل است. صوت از این رقم جداست. مسیر `evaluation/README-C3.md` برای plan و بستهٔ داور آماده است. سقف پذیرش پس از اجرا در `--provider-evidence` با سقف قبل از درخواست فرق دارد. قبل از G001 واقعی، محدودیت فراخوانی، توکن، کلید پروژه و سقف پیشینی باید در محیط اجرایی تنظیم و با مدرک بررسی شوند.
- داور انتخاب‌شده فقط بستهٔ A/B و معیارهای ۱۵گانه را می‌بیند. بعد از قفل نتیجه، کلید خصوصی A/B با دریافت‌کنندهٔ مجاز تطبیق داده می‌شود؛ نتیجهٔ fixture شاهد کیفیت مدل نیست.
