# White Hat | شواهد پذیرش S2 و گیت‌های باز

مرجع پذیرش، بخش‌های B و C در [راهنمای PR #2](../handoffs/SALEHE-ONBOARDING-EXECUTION-2026-11-14-FA.md) است. پذیرش رسمی تا ثبت CI روی SHA تحویلی و اجرای محیط مقصد باز است.

## شواهد بازتولیدپذیر

- آزمون Chromium پنل، BFF، Ktor و PostgreSQL با حساب‌ها و IdP مصنوعی. آزمون‌های backend، قرارداد مشترک و API نمونه نیز به commit تحویلی وصل شوند.
- نقش‌های OWNER، ADMIN، MEMBER و SUPPORT و کاربر خارج از workspace بررسی شوند. پشتیبان پیش‌فرض به متن تصمیم و مبلغ دسترسی ندارد. تغییر و حذف عضویت سمت سرور اعمال می‌شود. قابلیت‌های فعال‌سازی فعلی، توقف تحلیل جدید و فعال‌سازی بازخورد داوطلبانه‌اند.
- مسیر تمرین مهاجرت در `apps/web-bff/tools/legacy-cutover.mjs` با snapshot بسته SQLite و نگاشت صریح هویت و workspace کار می‌کند. نگاشت چندبه‌یک رد می‌شود. وضعیت فعال‌بودن حساب حفظ و رمزها، نشست‌ها و شناسه‌های احراز هویت قدیمی منتقل نمی‌شوند.
- تصمیم‌های دارای مالک معتبر در PostgreSQL با شناسهٔ قبلی و revision اولیه ثبت می‌شوند. تاریخچهٔ قدیمی run در برنامهٔ مهاجرت ردیابی می‌شود. قرارداد قدیمی برای هر run، snapshot و revision سازگار با صف جدید را اثبات نمی‌کند. این موارد وارد جدول عملیاتی runs و metering نمی‌شوند. نگهداری آرشیو کامل و قرارداد دسترسی به آن در handoff مالک تعیین شوند.
- نمونهٔ آزمایشگاهی شامل rollback بعد از INSERT، commit، نوشتن جدید روی مقصد، dump و restore در PostgreSQL مستقل و آزمون RLS است. بازیابی در محیط واقعی طبق ADR-010، پس از توقف writer و ثبت مرز آخرین write و حفظ تغییرهای جدید، به‌صورت forward restore یا rollback آزمایش‌شده انجام شود.

## شواهد لازم برای پذیرش رسمی

- نتیجهٔ CI از GitHub روی SHA تحویلی و تأیید مستقل مالک یا بازبین. منبع معتبر پنل با commit یا hash ثبت شود.
- اجرای Web E2E در محیط مقصد با IdP و TLS، session store پایدار و آزمون refresh/replay/logout، CSRF، role isolation، state و خطا در هفت Mode و دسترس‌پذیری. شواهد trace و OpenAPI drift ضمیمه شوند.
- انتقال روی کپی مجاز و تطبیق حساب، تصمیم، workspace، اجرا، مصرف و رسیدها. نگاشت مالک، حد دادهٔ قرنطینه، rollout، failover و rollback پس از write تصویب شوند.
- سیاست رضایت، نگهداری و حذف دادهٔ تصمیم، Audit، مالی و backup، نقش‌های ingress و سقف abuse/error در محیط مقصد تصویب و آزمون شوند.
